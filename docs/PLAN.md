# Career Log — 기획서

> 작성일: 2026-10-01 · 상태: 설계 확정 (MVP 착수 전)

---

## 1. 한 줄 요약

**하루에 한 일을 1시간 단위로 기록하고 일·주·월로 요약해 쌓는 1인용 업무 일지 서버.**

---

## 2. 왜 만드는가

이력서를 쓸 때마다 "내가 지난 2년간 뭘 했더라"를 기억에 의존해 복원한다. 복원되는 건 굵직한 프로젝트명 정도고, 실제로 설득력을 만드는 디테일(어떤 문제를 어떻게 풀었는지, 어떤 기술을 몇 시간 썼는지)은 사라진다.

→ **매일 1시간 단위로 기록을 쌓아두면, 이력서는 "쓰는 것"이 아니라 "뽑아내는 것"이 된다.**

이 제품의 모든 설계 판단은 이 한 문장에서 나온다. 기록의 입력 마찰을 최소화하고, 기록을 시간이 지나도 검색·집계 가능한 구조로 남긴다.

---

## 3. 사용자

- **단 한 명(본인).** 멀티테넌시·권한 체계·협업 기능은 설계에서 전면 배제한다.
- 접속 지점은 여럿: 집 PC, 회사 PC, 모바일.
- 회사 PC는 **프로그램 설치가 자유롭지 않다고 가정** → 브라우저만으로 완결되어야 한다.

## 4. 핵심 기능

### 4.1 시간 단위 기록 (주 기능)

- 일 보기는 **시간 순서로 흐르는 카드 리스트**다. 엔트리는 분 단위 `start`/`end`를 갖고, 카드 높이는 내용이 정한다(엄밀한 시간 비례 대신 **순서 + 완화된 눈금**).
  - **내용은 3줄까지** 보이고, 넘치면 **"더보기"**로 그 카드만 펼친다.
  - 카드 한 줄에 **칩 · 시간 … 수정 · 삭제**, 그 아래 내용.
  - **시간이 겹치는 기록**은 열로 나눠 보인다(2건 반반 / 3건 1/3).
- 기록 범위는 **하루 전체(00:00–24:00)**가 기본. **기록이 없는 앞/뒤(새벽·밤) 구간은 접어** 두고 필요하면 펼쳐 그 자리에 추가한다. 표시 중심 시간대는 **설정에서 지정**(기본 09:00–18:00).
- 오늘이면 **현재 시각선**으로 지금 위치를 표시한다.
- 엔트리는 **카테고리 + 태그 + 자유 텍스트**로 구성.
  - **카테고리**: 고정 집합. `업무` / `공부` / `회의` / `사이드` / `기타`. 집계의 축이 된다.
  - **태그**: 자유 입력, 자동완성. 프로젝트명·기술스택(`career-log`, `nextjs`, `postgres`)을 넣는다. 나중에 "이 기술을 몇 시간 했나"를 뽑는 근거.
  - **텍스트**: 한 일의 내용. 길이 제한 없음.
- **반복 입력 줄이기**: 새 기록 폼에서 같은 달의 **최근 활동을 칩**으로 한 번에 불러오고, **"직전과 동일"**로 바로 앞 기록을 복제한다.
- **연속 같은 기록 자동 병합**: 저장할 때, 시간을 뺀 내용(카테고리+태그+텍스트)이 같고 시간이 **맞닿거나 겹치는** 기록은 하나로 합친다(앞뒤로 연쇄). 중간에 빈 시간이 있으면 합치지 않는다. 표시가 아니라 실제 기록을 합친다.
- 타임라인 왼쪽 눈금의 **시간별 `+`** 로 그 시각에 바로 추가하고, 카드에서 **수정·삭제**한다(좁은 카드는 눌러서 편집).
- 모든 기록은 **언제든 수정·삭제 가능**. 과거 기록도 제한 없이 편집된다.

### 4.2 기록 알람 (입력 마찰 제거)

기록은 "나중에 몰아서 쓰면" 반드시 실패한다. 그래서 **쓰는 시점을 그 시간 안으로 끌어온다.**

- PWA로 설치한 클라이언트에 **매 정시 Web Push 알림**이 뜬다.
- 알림을 클릭하면 **해당 시간 슬롯의 입력 폼이 바로 열린다**(홈 화면을 거치지 않는다).
- 알람 시간대·요일은 설정에서 조정(기본: 평일 09–18시).
- 이미 기록된 슬롯은 알림을 보내지 않는다.

### 4.3 계층 요약

기록은 아래로 갈수록 상세하고, 위로 갈수록 압축된다.

| 레벨 | 생성 시점 | 내용 |
|---|---|---|
| 시간 | 사용자가 직접 | 그 1시간에 한 일 |
| **일간 요약** | 매일 23:50 | 그날 엔트리 전체를 요약 |
| **주간 요약** | 일요일 23:55 | 그 주 일간 요약 7개를 요약 |
| **월간 요약** | 말일 23:55 | 그 달 주간 요약들을 요약 |

- 요약은 **Claude API(`claude-opus-5`)가 초안을 생성**하고, 사용자가 **확인·수정**한다. AI 생성본인지 사람이 고쳤는지 메타데이터로 구분해 보관한다.
- 수동 재생성 버튼 제공(기록을 나중에 보강했을 때).
- `ANTHROPIC_API_KEY`가 없으면 자동 생성은 건너뛰고 **빈 요약 + 수동 작성 UI**로 폴백한다. 기능이 죽지 않는다.
- 비용은 무시 가능한 수준이다(일간 요약 1건 ≈ 입력 1K·출력 300 토큰 ≈ $0.013, 월 $0.5 미만).

### 4.4 달력 뷰

기본 화면. 정보 밀도를 레벨별로 다르게 준다.

```
┌────────────────────────────────────────────────────────┐
│  < 2026년 10월 >                      [월] [주] [일]    │
├────────────────────────────────────────────────────────┤
│  월    화    수    목    금    토    일                  │
│  ─────────────────────────────────────                 │
│  28    29    30     1     2     3     4                │
│                    API   배포…  ·     ·                 │
│                    리팩…                                │
│  ┌──────────────────────────────────────────┐          │
│  │ 📅 10/1 – 10/4 주간 요약                  │          │
│  │ 인증 모듈을 세션 기반으로 재작성하고…      │          │
│  └──────────────────────────────────────────┘          │
└────────────────────────────────────────────────────────┘
```

- **월 그리드**가 기본. 각 주 아래(또는 옆)에 **그 주의 요약이 항상 노출**된다.
- **일 셀**에는 그날 요약의 **첫 줄만** 보이고 넘치면 `…`로 자른다.
- **일 셀 클릭** → 그날의 **시간 단위 전체**를 보는 상세 뷰로 진입. 여기서 편집한다.
- 카테고리는 색으로 구분, 태그로 필터링.
- **월 달력 1회 렌더 = 원격 fetch 1회**(월 파일 1개). 이 제약이 저장 구조를 결정한다(§7-2).

### 4.5 저장 — 원격 정본 (로컬 무보관)

**기록의 정본은 서버 디스크가 아니라 private GitHub 레포다.** 홈서버에는 과거 기록을 보관하지 않는다.

```
읽기:  메모리 LRU 캐시 → (miss) GitHub Contents API → 캐시 적재 → 응답
쓰기:  메모리 즉시 반영 + 로컬 쓰기 큐 적재 → 10초 디바운스 → GitHub 커밋 → 큐 제거
```

- 홈서버 디스크에 영구적으로 남는 기록은 **없다.** 남는 것은 (a) 프로세스 메모리의 LRU 캐시(최근 24개월, 재시작 시 소멸), (b) **아직 원격에 반영되지 않은 쓰기만** 담는 로컬 큐뿐이다.
- **쓰기 큐**는 과거 기록 보관이 아니라 유실 방지 스풀이다. 평상시 0건이며, 네트워크가 일주일 끊겨도 15KB 수준이다. 원격 반영에 성공하면 즉시 삭제된다. 이게 없으면 네트워크 단절 중 입력한 기록이 조용히 사라진다.
- **모든 쓰기가 곧 git 커밋**이므로 버전 이력이 자동으로 쌓인다. 별도의 주간 백업 잡은 필요 없다.
- 동시 수정은 blob `sha` 기반 낙관적 동시성으로 처리한다. 409 충돌 시 재읽기 후 병합 재시도.
- 타이핑마다 커밋하지 않도록 **10초 디바운스** 후 변경분을 1커밋으로 묶는다.

**이 선택이 감수하는 비용** (근거는 [DECISIONS.md](./DECISIONS.md) ADR-004):

| 리스크 | 완화 |
|---|---|
| GitHub 장애·토큰 만료 시 과거 기록 조회 불가 | 캐시에 있는 범위는 계속 조회 가능. UI에 저하 상태 명시 |
| 쓰기 지연 200–800ms | 낙관적 UI(즉시 반영 후 백그라운드 동기화) |
| 네트워크 단절 중 쓰기 유실 | 로컬 쓰기 큐 + 지수 백오프 재시도 |
| 사본이 사실상 1벌 | 월 1회 다른 저장소(또는 같은 레포의 `snapshots/` 경로)로 tar.gz 스냅샷 |

### 4.6 복구 / 이관

- UI에서 **커밋 이력 조회 → 특정 시점 상태 복원**을 지원한다(Contents API + Commits API).
- 전체 데이터 **JSON 내보내기**를 제공한다. 서비스를 버려도 기록은 남는다.

### 4.7 이력서 / 지원 내역 (2단계)

MVP에는 **포함하지 않는다.** 다만 저장 레이아웃에 확장 지점만 열어둔다.

- 지원 내역: 회사·직무·단계·일자·결과·회고
- 이력서: 섹션 단위 저장, 버전 관리, 지원 건과 연결
- **자동 작성**: 기간·태그를 지정하면 누적된 요약과 엔트리를 근거로 경력기술서 초안을 생성

→ 상세는 [ROADMAP.md](./ROADMAP.md).

## 6. 비기능 요구사항

| 항목 | 목표 |
|---|---|
| 디스크 | **과거 기록 0바이트.** 상주 사용량은 앱 이미지 + 미동기화 큐(≤ 수십 KB)뿐 |
| 빌드 | **서버에서 빌드하지 않는다.** 외부에서 빌드한 standalone 이미지를 pull |
| 메모리 | 앱 컨테이너 RSS 250MB 이하 (LRU 캐시 24개월 상한 포함) |
| 응답 | 캐시 적중 시 100ms 이내 / 캐시 미스 시 1s 이내(원격 1회 fetch) |
| 가용성 | 원격 장애 시 **캐시 범위 조회 + 쓰기 큐잉**으로 저하 동작. 앱은 죽지 않음 |
| 데이터 안전성 | sha 기반 낙관적 동시성. 커밋 실패는 큐에 남아 재시도되며 조용히 유실되지 않음 |
| 보안 | 외부 노출 전제. HTTPS 종단, 세션 쿠키 httpOnly+Secure, 레이트 리밋. PAT는 서버 환경변수로만 보관 |
| 타임존 | `Asia/Seoul` 고정. 날짜 경계는 로컬 기준 |

## 7. 핵심 설계 결정 (요약)

전체 근거는 [DECISIONS.md](./DECISIONS.md) 참조.

| # | 결정 | 한 줄 근거 |
|---|---|---|
| 1 | Next.js 풀스택(TypeScript) | 컨테이너 1개로 프론트+API+스케줄러를 모두 담는다 |
| 2 | **월 1파일 + 인덱스 파일** | 네트워크가 정본이므로 요청 수가 곧 응답 속도. 달력 렌더를 1 fetch로 묶는다 |
| 3 | **RDB 없음** | 데이터가 JSON 문서 구조이고 단일 사용자다. 조인도 동시성도 없다 |
| 4 | **원격(GitHub) 정본, 로컬 무보관** | 사용자 요구. 감수 비용과 완화책은 §4.5 표 |
| 5 | **Redis 없음, 프로세스 메모리 LRU** | 캐시가 외부 프로세스일 이유가 없다. 데이터보다 Redis가 무겁다 |
| 6 | **로컬 쓰기 큐(미동기화분 한정)** | 네트워크 단절 중 쓰기 유실을 막는 최소 장치 |
| 7 | PWA + Web Push | 회사 PC에 설치 프로그램 없이 OS 알림을 띄우는 유일한 길 |
| 8 | Claude API 요약, 키 없으면 폴백 | 외부 의존이 기능 전체를 죽이지 않게 한다 |
