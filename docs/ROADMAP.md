로그인 상태에서 `/login` 접근 시 홈으로, 로그아웃 후 재차단, 6회 실패 시 429,
변조 토큰 거부.

> ESLint는 10이 아니라 9를 쓴다. `eslint-config-next` 16이 번들한
> `eslint-plugin-react`가 ESLint 10의 rule context 변경과 호환되지 않는다.
> TypeScript도 7이 아닌 5.9를 쓴다. 둘 다 상류가 따라오면 올린다.

### 1-6. 복구 ✅
- [x] 커밋 이력 조회 (`/api/sync/history`) — 데이터 레포 최근 커밋 목록
- [x] 특정 시점 복원 (`/api/sync/restore`) — 과거 트리로의 순방향 커밋(이력 보존),
      미동기화분 있으면 거부. 복원 후 캐시 무효화
- [x] 전체 JSON 내보내기 (`/api/export`) — 로컬 2차 사본·탈출구
- [x] `/settings/data`: 내보내기 버튼 + 커밋 이력 + "이 시점으로 복원"
- [~] 월 1회 tar.gz 스냅샷 — **보류(의도적)**. 같은 레포에 넣으면 git 이력과
      중복이라 실가치 없음. 진짜 2차 사본은 사용자가 내려받는 JSON 내보내기가 담당.
      레포 밖 2차 백업이 필요해지면 그때 별도 백엔드(예: Drive) 검토.

**완료 조건**: 한 달간 실제로 매일 기록을 쌓고, 주간 요약이 자동 생성되며, 서버를 날려도 복구된다.
→ 저장·요약·알람·복구 모두 구현. 서버 복구는 git clone + docker compose up 으로 성립(ADR-004).

## 2단계 — 커리어 관리 (성과 모음 중심)

업무 일지의 강점(쌓인 기록)을 살려, **기록에서 성과를 뽑아 모으는 것**을 2단계 핵심으로 잡았다.
스택이 좁아도 "무엇을·어떻게·어떤 효과"가 쌓이는 게 이력서/포트폴리오의 근거가 된다.

### 2-1. 성과 모음 (brag doc) ✅
- [x] `meta/achievements.json`(career-db, 기록과 분리) + 성과 저장소 CRUD
- [x] **수동 "성과 뽑기"** — 범위(이번 달/지난 달/기간) 지정 → AI가 기록에서 후보 추출(저장 안 함) → 체크리스트에서 담을 것만 저장
- [x] 성과는 **한 줄(요약)** 또는 **상세(문제→접근→결과+기술)** — 상세는 뽑아낼 수 있을 때만. ⭐(후보)·주제·근거 날짜·수정/삭제·직접 추가
- [x] 성과 추출 프롬프트 설정 커스텀(system/guide, JSON 형식은 코드 고정) — ADR-012

### 2-2. (이후) 지원 추적 · 이력서 — 보류/후속
- [ ] 지원 내역(회사·직무·단계·결과·회고), 단계별 칸반
- [ ] 이력서 섹션 CRUD + 버전 관리

**완료 조건**: 매일 쌓는 기록에서 성과가 큐레이트되어 모인다. (경력기술서·포트폴리오로 **내보내기**는 3단계)

## 3단계 — 자동 작성 (이 프로젝트의 목적지)

- [ ] **성과 모음(2-1) 내보내기** — ⭐ 성과를 회사·테마별로 조립해 **경력기술서**(요약 bullet) / **포트폴리오**(문제→접근→결과 서사) 초안 생성
- [ ] 기간·태그를 지정하면 누적 요약·엔트리를 근거로 경력기술서 초안 생성
- [ ] 생성된 문단마다 **근거 기록으로 역추적**(성과의 `sourceDates`)
- [ ] 채용공고 텍스트를 넣으면 그에 맞춰 강조점을 바꾼 버전 생성
- [ ] 기술스택별 누적 시간 통계 (태그 집계)

**완료 조건**: 이력서 초안이 기억이 아니라 기록에서 나온다.
