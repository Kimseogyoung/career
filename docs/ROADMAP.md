## 2단계 — 커리어 관리 (성과 모음 중심)

업무 일지의 강점(쌓인 기록)을 살려, **기록에서 성과를 뽑아 모으는 것**을 2단계 핵심으로 잡았다.
스택이 좁아도 "무엇을·어떻게·어떤 효과"가 쌓이는 게 이력서/포트폴리오의 근거가 된다.

### 2-1. 성과 모음 (brag doc) ✅
- [x] `meta/achievements.json`(career-db, 기록과 분리) + 성과 저장소 CRUD
- [x] **수동 "성과 뽑기"** — 범위(이번 달/지난 달/기간) 지정 → AI가 기록에서 후보 추출(저장 안 함) → 체크리스트에서 담을 것만 저장
- [x] 성과는 **한 줄(요약)** 또는 **상세(문제→접근→결과+기술)** — 상세는 뽑아낼 수 있을 때만. ⭐(후보)·주제·근거 날짜·수정/삭제·직접 추가
- [x] 성과 추출 프롬프트 설정 커스텀(system/guide, JSON 형식은 코드 고정) — ADR-012

### 2-2. 추천 포지션 ✅ (지원 추적 대신)
- [x] 게임잡에서 고른 직무(여러 개)의 공고를 탭을 열 때 오래됐으면(12시간) 자동 수집 — 직접 할 일 없음 (ADR-017)
- [x] 규칙 기반 적합도(기술 일치 60 · 경력 25 · 성과로 증명 15) + 맞는 기술·부족한 기술·근거 성과
- [x] 표 + 펼치기 화면(`/career/positions`), 적합도·마감·최신 정렬, 새 공고·⭐·숨김. 푸시 알림은 하지 않음
- [ ] ~~지원 내역(회사·직무·단계·결과·회고), 단계별 칸반~~ → 직접 입력할 일이 많아 하지 않음(2026-10-19). 추천으로 대신
- [ ] ~~이력서 섹션 CRUD + 버전 관리~~ → 3-2 버전 관리로 흡수

### 2-3. 공개 Showcase (읽기 전용) ✅
로그인 화면에서 "비밀번호 없이 둘러보기"로 들어가는 **공개 읽기 전용 포트폴리오**. 이 서버 자체를
라이브 포트폴리오로 쓴다. (3단계 '내보내기'가 문서라면, 이건 상시 공개 웹페이지)

**공개 페이지 구성 (`/showcase`)**
- **홈(개요)**: 2줄 자기소개 → 기술 스택 → 경력 사항 → 프로젝트 → ⭐ 대표 성과(별표한 것) + "전체 보기"
- **성과**: 각 성과를 **문제·접근·결과 풀버전**으로. 기본 **최신순**, **테마별 ↔ 프로젝트별** 토글(그룹 내에서도 최신순)
- **프로젝트**: 프로젝트(명·기간·소개) 블록 + 그 프로젝트의 성과
- 근거 날짜는 기간 라벨만(일지로 가는 링크 없음). 일지·요약·설정은 **절대 비노출**

**데이터 모델 (career-db `meta/`, ADR-012)**
- [x] `achievements.json`: 기존 + `projectId:string`, `hidden?:boolean`(**기본 공개 · 숨김 옵션**). 기존 `star`(⭐) = **홈 대표 노출**
- [x] `projects.json`(신규): `{id, name, period, description, order}`
- [x] `profile.json`(신규): `{intro(2줄 소개), techStack:[{label,items[]}], career:[{org,role,period,note}]}`

**커리어 앱(내부) 화면** (서브탭: 성과 · 프로젝트 · 내 정보)
- [x] **성과**(기존): **프로젝트 선택**(등록 시) + ⭐별표(홈 대표) + **숨김 토글**(기본 공개) + 최신순
- [x] **프로젝트 탭**(신규): 프로젝트명·기간·소개 CRUD. 성과는 이 프로젝트에 연결
- [x] **내 정보 탭**(신규): 2줄 소개 + 기술 스택(그룹별) + 경력 사항. 홈 노출 순서 = 소개→기술 스택→경력

**공개 노출 (보안 핵심 — 제약 #6·#7, ADR-013)**
- [x] 미들웨어 화이트리스트로 **`/showcase` 와 하위 경로만** 개방(나머지·모든 `/api/*` 로그인 유지)
- [x] 공개는 **SSR 전용** — `loadShowcase`가 서버에서 `meta/`(profile·projects·achievements, `hidden` 제외)만 읽음. 일지·요약·설정·비밀값 비노출. **별도 공개 JSON API는 두지 않음**(표면 최소화)
- [x] `/showcase`(홈: 소개→기술→경력→프로젝트→⭐대표) · `/showcase/achievements`(풀버전 + 테마/프로젝트 토글). 공개 페이지에선 앱 헤더 숨김

**구현 순서**: ① 데이터 모델 + 커리어 입력 UI(프로젝트·내 정보·성과 공개/프로젝트 선택) → ② 공개 API + 미들웨어(ADR) → ③ `/showcase` 페이지

**완료 조건**: (2-1 ✅) 매일 쌓는 기록에서 성과가 큐레이트되어 모인다. (2-3) 숨김 처리하지 않은 성과가 비로그인
방문자에게 홈·성과·프로젝트로 보이고(⭐별표는 홈 대표로), 일지·요약·설정·비밀값은 전혀 노출되지 않는다. (경력기술서·포트폴리오 문서 **내보내기**는 3단계)

> (추후) 성과→테마 맵·타임라인, 채용공고 맞춤 강조 — 3단계 내보내기와 데이터 공유

## 3단계 — 자동 작성 (이 프로젝트의 목적지)

흐름은 **기록 → 성과(2-1, 사람이 고름) → 문서** 하나뿐이다. 요약에서 문서로 바로 가지 않는다(ADR-016).
결과물은 한국어만, 형식은 **화면 미리보기 + 인쇄용 화면**(브라우저 PDF 저장)으로 충분하다. `.docx` 는 만들지 않는다.

### 3-1. 조립 내보내기 (AI 없음)
- [x] 프로젝트 → **회사(경력 항목) 연결** 필드. 직접 고르지 않으면 기간이 가장 많이 겹치는 경력으로 추정
- [ ] **경력기술서**: 사용자가 주는 양식대로 회사 → 프로젝트 → 성과를 코드로 조립 (양식 대기 중)
- [x] **포트폴리오**: 내 정보 → 경력 목록(성과 없음) → 프로젝트(최신순, 회사는 표시만) → 문제·접근·결과 + 사진. 회사별 묶음은 경력기술서 몫 (`/career/export`, ⭐만·사진 빼기)
- [x] 미리보기 · 인쇄용 화면(A4, 브라우저 PDF 저장). 비공개 화면에서만(Showcase 비노출)

### 3-2. 버전 관리 ✅
- [x] 마음에 든 결과만 이름 붙여 `meta/resumes/` 에 저장 · 목록 · 열기 · 삭제 (2-2 "이력서 버전 관리"를 흡수) — 내보내기 "이 상태로 저장", `/career/export/saved/<id>`
- [x] 저장본은 조립 당시 내용을 그대로 고정(원본 성과가 바뀌어도 저장본은 안 바뀜) + 근거 성과 id 보관. 저장 뒤 원본이 고쳐지거나 지워진 건수를 안내(저장본은 그대로)

### 3-3. AI 다듬기 + 근거 역추적
- [ ] 문장 다듬기는 AI, 실패하면 3-1 조립본 그대로(제약 6)
- [ ] 문단마다 근거 성과 id 를 함께 받는다 — 없는 id 는 버리고, **원문에 없는 숫자가 나오면 경고**
- [ ] 문단 옆 근거 성과·날짜 → 그날 일지로 이동

### 3-4. 채용공고 맞춤
- [ ] 공고 텍스트 → 맞는 성과 선택·순서·강조 변경 + **"공고엔 있는데 근거가 없는 항목"** 표시. 결과는 3-2 버전으로 저장

### ~~3-5. 기술별 누적 시간~~ — 하지 않음
- ~~월간 요약의 태그 통계(`topTags`)를 합산~~ → 이력서·포트폴리오에 쓸 데가 없어 제외(2026-10-19, 아래 "하지 않기로 한 것")

**완료 조건**: 이력서 초안이 기억이 아니라 기록에서 나오고, 모든 문단이 근거 성과로 되돌아간다.
